The V2 standard

A good alert tells the person who receives it what broke, how bad it is, and what to do. Eight rules, each with an example.

Say what failed, where, and by how much

The message alone should be enough to know what is wrong.

Not thisError OccurredThisEmail send failure rate above 5% over 10m

Report a problem, never a status

If nobody has to do anything, it is a log line. Delete the alert.

Not thisi am aliveThisNo alert at all

Use real names

Application, component and operator name a real thing someone can find.

Not thisDefaultThisdispatch-queue

Link the rule that fired

The responder opens the Grafana rule in one click.

Not thisNo linkThishttps://grafana…/alerting/rule/…

Clear when the problem is handled

No alert stays on for days, fires again and again, or flips on and off.

Not thisOn for 7 of 7 daysThisFires, gets handled, clears

Don't send what your own dashboard hides

If every panel you own filters an alert out, fix or delete it at the source.

Not thisA filter that hides the nodeThisThe alert is gone, the filter too

Only in V2

State the impact as what users see

Describe the symptom people experience, not the technical cause.

Not thisQueue consumer lag highThisCustomers get notifications late

Give a runbook

An https link to the steps the responder should take.
